# Prometey

**Prometey** — прошивка для ESP32, которая управляет водяным тёплым полом: до 8 комнат с моторизованными термоклапанами и PID-регулированием, котлом ECTOControl V2 по RS485/Modbus RTU, реле через расширители PCF8574, а также интеграцией с MQTT и Home Assistant. Встроенный веб-интерфейс хранится в LittleFS и обслуживается самим устройством.

Целевое железо — плата **Kincony KC868-A16** (16 релейных выходов, Ethernet-порт, шина RS-485). Проект написан на Arduino framework для ESP32 и собирается через PlatformIO.

---

## Возможности

- Управление **до 8 комнатами** с индивидуальными настройками PID (kP/kI/kD).
- **До 9 клапанов**, каждый привязан к релейному каналу; логическое открытие 0–100 % пересчитывается в физическое 70–100 % 60-секундного окна.
- Работа с котлом **ECTOControl V2** по RS485/Modbus RTU: режимы Off/Heat/Auto, уставки отопления и ГВС, показания температуры, модуляции, пламени и ошибок.
- Погодная кривая в режиме Auto с коэффициентами K/B/P/I и PI-коррекцией по средней ошибке рабочих комнат.
- Управление реле (например, насосом) через два расширителя **PCF8574** по I2C.
- **MQTT**-команды и публикация состояний, автообнаружение **Home Assistant**.
- Встроенный **веб-интерфейс** с вкладками Status, Control, MQTT, Network, Boiler, Rooms, Logger и Backup.
- **OTA**-обновление прошивки и файловой системы, полный бэкап и восстановление конфигурации.
- Удалённое логирование и версия прошивки, внедряемая из git при сборке.

## Как это работает

### Комнаты и PID

Температура каждой комнаты приходит по MQTT: у комнаты свой topic, JSON-поле необязательно — голое число в payload тоже допустимо. Если датчик не обновлялся **более 2 часов**, PID комнаты останавливается, а клапаны переходят в аварийное открытие.

PID пересчитывается **каждые 5 минут**. Коэффициенты kP/kI/kD задаются в профиле комнаты; интегральная составляющая ограничена диапазоном 0–100.

### Клапаны

Клапан — это выход, привязанный к релейному каналу. Логические 0–100 % открывания отображаются в физические **70–100 %** 60-секундного окна: ниже примерно 70 % клапан практически не пропускает тепло. Длительность окна сейчас жёстко задана в коде и составляет 60 секунд.

### Котёл и погодная кривая

В режиме **Auto** уставка отопления рассчитывается по квадратичной погодной кривой от уличной температуры:

- коэффициент **K** масштабирует кривую;
- коэффициент **B** задаёт параллельный сдвиг;
- **P** и **I** управляют PI-коррекцией по средней ошибке рабочих комнат (I — интегральная составляющая в секунду);
- коррекция ограничена **±10 °C**, а интеграл сохраняется в `/boiler.bin`.

Уставка Auto ограничена диапазоном **`[minSetPoint, 80]`**. `minSetPoint` по умолчанию равен 50 °C — это нижний предел температуры подачи для неконденсационных котлов. Ручная уставка ограничена диапазоном **`[30, 80]`**.

### Интерлок отопления

Если нет комнат, требующих нагрева (ошибка больше **0.2 °C**), в течение двух тиков подряд (примерно 10 минут), центральное отопление отключается. Повторное включение происходит по требованию, но не раньше чем через **10 минут** после отключения. При отключённом отоплении клапаны аварийно открываются на 100 %, а датчик `valveOpening` в MQTT/Home Assistant продолжает показывать логическое значение PID.

Состояние котла сохраняется в `/boiler.bin` каждые **60 секунд**. При появлении кода ошибки котла отопление выключается.

## Требования

### Оборудование

- Плата **Kincony KC868-A16** на ESP32 с Ethernet и RS-485.
- Котёл **ECTOControl V2**, подключённый по RS485/Modbus RTU.
- Моторизованные термоклапаны, подключённые к релейным выходам.
- Два расширителя **PCF8574** для реле.
- Датчики температуры комнат, публикующие значения в MQTT.
- Опционально — источник уличной температуры в MQTT.

Распиновка, заданная в прошивке:

| Интерфейс | Параметры |
| --- | --- |
| RS485 (Serial2) | RX = GPIO16, TX = GPIO13, 8N1, таймаут 200 мс |
| I2C (Wire) | GPIO4 / GPIO5, 100 кГц |
| PCF8574 | адреса `0x24` и `0x25` |

Количество сущностей: `ROOMS_COUNT = 8`, `VALVES_COUNT = 9`.

### Программное окружение

- **PlatformIO** для сборки и прошивки.
- **Node.js и npm** — только если вы собираете веб-интерфейс из исходников.
- **make** и **curl** — для OTA-деплоя.
- Базовые навыки работы с PlatformIO и Node.js.

Юнит-тестов в репозитории нет: главная локальная проверка — успешная компиляция прошивки.

### Окружения PlatformIO

| Окружение | Назначение |
| --- | --- |
| `kc868a16` | Production-сборка и прошивка по USB |
| `kc868a16_ota` | То же, но прошивка по сети через espota; адрес и пароль берутся из `.env` |
| `kc868a16_dev` | Нерабочее окружение, см. раздел «Известные ограничения» |

## Быстрый старт (USB)

### 1. Сборка

```bash
pio run -e kc868a16
```

### 2. Прошивка по USB

```bash
pio run -e kc868a16 -t upload
```

Монитор последовательного порта работает на скорости **115200**:

```bash
pio device monitor
```

### 3. Загрузка веб-интерфейса

```bash
pio run -e kc868a16 -t uploadfs
```

> **Важно:** `uploadfs` **стирает весь LittleFS** — `/config.bin`, `/boiler.bin` и все `/room_<i>.bin`. Все настройки будут потеряны. Перед повторной загрузкой UI сделайте полный бэкап через вкладку **Backup** (или `make backup`, либо `GET /api/config/backup`), а после загрузки восстановите его через вкладку Backup или `make restore ZIP=...`.

### 4. Подключение к сети

- Подключите кабель **Ethernet**. Устройство получает адрес по DHCP; статический IP не настраивается.
- Приоритет всегда у Ethernet. Если ссылка не появилась примерно за **15 секунд**, устройство поднимает резервную точку доступа **`Prometey_<MAC>`** (по умолчанию без пароля) со стандартным адресом ESP32 AP **192.168.4.1**.
- Веб-панель доступна по адресу `http://<IP-устройства>/` (порт 80).
- Wi-Fi в штатном режиме настраивается во вкладке **Network**. Если кабель не подключён, устройство перейдёт в режим STA.

### 5. Первичная настройка

Рекомендуемый порядок во вкладках веб-интерфейса:

1. **Network** — Ethernet/Wi-Fi и параметры доступа.
2. **Rooms** — комнаты и привязанные к ним клапаны.
3. **Boiler** — драйвер, Modbus-адрес и скорость, коэффициенты K/B/P/I, `minSetPoint`, датчик уличной температуры.
4. **MQTT** — при необходимости подключение к брокеру и Home Assistant.

Настройки комнат, клапанов, котла и MQTT применяются **после перезагрузки** (кнопка Reboot во вкладке Status; UI делает это автоматически). Настройки сети применяются **сразу**, без перезагрузки. Команды со вкладки Control также применяются **сразу**.

## Веб-интерфейс

В шапке панели отображаются версии **FW** и **UI**. Вкладки идут в фиксированном порядке.

| Вкладка | Назначение | Когда применяется |
| --- | --- | --- |
| **Status** | Информация об устройстве, свободный heap, uptime, причина последнего сброса, ready-статус сервисов, кнопка перезагрузки. Автообновление примерно раз в 10 секунд. | — |
| **Control** | Живая работа с опросом примерно раз в 3 секунды: режим котла Off/Heat/Auto, уставка отопления 30–80 °C с шагом 0.1 (в Auto дополнительно ограничена снизу `minSetPoint`), ГВС вкл/выкл и уставка, текущие температуры отопления и ГВС, модуляция, уличная температура, пламя, ошибка; комнаты — вкл/выкл и уставка 16–32 °C. | Сразу |
| **MQTT** | Хост, порт, логин, пароль, включение HA discovery и префикс, топики command/state. | После перезагрузки |
| **Network** | Веб-компонент `edn-network-ui`: Wi-Fi STA/AP, сканирование сетей. | Сразу, без перезагрузки |
| **Boiler** | Драйвер ECTOControl V2, Modbus-адрес и скорость, коэффициенты погодной кривой K/B/P/I, `minSetPoint`, внешний датчик уличной температуры (MQTT-topic и JSON-поле), живой SVG-график погодной кривой, кнопка удаления `/boiler.bin`. | После перезагрузки |
| **Rooms** | CRUD комнат и привязанных клапанов (заполняется весь профиль; рекомендуемые стартовые значения подставляются), runtime-показания PID, сброс всех состояний комнат. | После перезагрузки |
| **Logger** | Настройки удалённого логирования (веб-компонент `edu-log-ui`, `/api/log/settings`). | — |
| **Backup** | Скачать полный архив `config.bin` + `boiler.bin` + `room_*.bin` (`prometey-config.zip`) или только `config.bin`; загрузить архив обратно с валидацией, атомарной записью и немедленной перезагрузкой. | Немедленная перезагрузка после загрузки архива |

> **Важно:** бэкапы содержат пароли Wi-Fi и MQTT в открытом виде. Храните их как секреты и не коммитьте локальные копии.

### Удалённое логирование

Адрес сервера задаётся во вкладке **Logger**. В прошивке есть временный hardcode-дефолт вида `http://<log-host>:5555/_bulk` — замените его на адрес своего лог-сервера.

## Home Assistant и MQTT

### Базовые топики

Состояние устройства публикуется в:

```text
prometey/<chip>/state
```

Команды принимаются в:

```text
prometey/<chip>/set
```

Здесь `<chip>` — chip ID устройства. Команды в топик `set` передаются JSON-ключами:

- `centralHeatingMode`
- `centralHeatingSetPoint`
- `hotWaterMode`
- `hotWaterSetPoint`

### Комнаты и уличная температура

У каждой комнаты есть настраиваемые `mqttCommandTopic` и `mqttStateTopic`. Команды комнаты имеют вид `{"mode": ...}` и `{"setPoint": ...}`.

Topic уличной температуры задаётся во вкладке **Boiler**. JSON-поле необязательно: если поле не указано, payload воспринимается как голое число.

Состояния публикуются при изменении, но не чаще одного раза в **500 мс**.

### Home Assistant discovery

Автообнаружение включено по умолчанию, префикс — `homeassistant`. В Home Assistant появляются:

- климатические сущности котла (off/heat/auto) и водонагреватель ГВС;
- бинарные сенсоры пламени, ГВС и ошибки;
- сенсоры модуляции и другие служебные показатели;
- для каждой комнаты — climate с диапазоном 16–32 °C и шагом 0.1, а также сенсор открытия клапана.

В Home Assistant устройство отображается с именем **Prometey**, модель — **KC868-A16**, производитель — **Kincony**. Идентификатор устройства строится по chip ID, а версия прошивки (`sw_version`) внедряется при сборке из git.

## OTA-деплой (make)

OTA позволяет обновлять прошивку и файловую систему по сети. Адрес и пароль хранятся в неотслеживаемом файле `.env`; шаблон находится в `.env.example`.

### Настройка `.env`

```bash
cp .env.example .env
```

Заполните:

- `PROMETHEY_OTA_IP` — IP-адрес устройства;
- `PROMETHEY_OTA_AUTH` — пароль, совпадающий с паролем, зашитым в прошивку. Значение не должно содержать символы `"` и `\`.

Реальный пароль в этот README не приводится. Не коммитьте `.env`.

### Цели Makefile

| Команда | Что делает |
| --- | --- |
| `make deploy` | Полный конвейер: OTA-прошивка → ожидание загрузки → бэкап конфигов → OTA-загрузка LittleFS с UI → ожидание → восстановление конфигов → финальная проверка `/api/status` |
| `make firmware` | Только прошивка firmware по OTA |
| `make ui` | Только загрузка UI в LittleFS по OTA (deploy сам делает бэкап и restore) |
| `make backup` | Скачать конфигурацию в `build/deploy/prometey-config-<timestamp>.zip` и обновить `latest.zip` |
| `make restore` | Восстановить конфигурацию из `build/deploy/latest.zip`; можно указать `ZIP=<путь>` |
| `make status` | Показать ответ `GET /api/status` |
| `make wait-for-boot` | Дождаться, пока устройство ответит на `/api/status` |
| `make help` | Показать справку по целям |

Все цели, кроме `make help`, требуют наличия `.env`.

`make deploy` автоматически делает бэкап перед загрузкой UI, потому что `uploadfs` стирает LittleFS. Файл бэкапа сохраняется в `build/deploy/`, рядом обновляется `latest.zip`.

Переопределяемые переменные: `HOST`, `PIO`, `WAIT_INITIAL`, `WAIT_TIMEOUT`, `POLL_INTERVAL`, `BACKUP_DIR`, `ZIP` и другие.

```bash
make deploy
make status
make restore ZIP=build/deploy/latest.zip
```

Обновить прошивку по сети можно и любым клиентом ArduinoOTA — пароль берётся из `.env`. Загрузки прошивки через веб-интерфейс нет.

## Сборка UI из исходников

Исходники панели находятся в `frontend/` (Preact + TypeScript + Vite). Сборка сразу пишет результат в `data/`, откуда PlatformIO загружает его в LittleFS.

```bash
cd frontend
npm install
npm run build
```

> **Важно:** Vite использует `emptyOutDir: true`, поэтому сборка **удаляет незатрекованные файлы** в `data/`. Если там лежат локальные `.bin`-фикстуры, сохраните их заранее.

После сборки загрузите файловую систему:

```bash
pio run -e kc868a16 -t uploadfs
```

Перед `uploadfs` обязательно сделайте бэкап (см. предупреждение в «Быстром старте»). Для OTA-варианта используйте `make ui` или `make deploy`.

## Безопасность

- Веб-интерфейс и HTTP API **не имеют аутентификации** и рассчитаны на доверенную локальную сеть. **Не публикуйте устройство в интернет** и не выставляйте его наружу без VPN.
- Файл `/config.bin` скачивается напрямую и содержит пароли Wi-Fi и MQTT **в открытом виде**.
- Архивы LittleFS-бэкапов тоже содержат секреты. Храните их как конфиденциальные данные.
- Локальные копии бэкапов (`configs/`, `build/`) не коммитьте в репозиторий.
- Резервная точка доступа по умолчанию **без пароля**. Первичную настройку выполняйте из доверенной сети; если схема доступа меняется, закройте AP паролем во вкладке **Network**.

## Известные ограничения

- Изменения, затрагивающие тайминги, структуру хранения или MQTT-топики, нельзя полноценно проверить без реального железа.
- Структура бинарных конфигов зафиксирована. Совместимость между версиями прошивки обеспечивает механизм миграций; перед обновлением рекомендуется сделать полный бэкап.
- Окружение `env:kc868a16_dev` нерабочее: оно расширяет несуществующее `env:kc868a2`. Не используйте его.
- Полного справочника по HTTP API и MQTT-контракту в этом README нет — см. [AGENTS.md](AGENTS.md). Детали вкладок SPA описаны в [frontend/README.md](frontend/README.md).
- Юнит-тестов нет; основная локальная проверка — компиляция прошивки.
